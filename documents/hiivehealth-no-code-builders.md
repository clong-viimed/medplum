# HiiveHealth No-Code Builders → Medplum Mapping

Last updated: 2026-07-13

## Purpose

This document tracks the no-code configuration tools that exist in HiiveHealth and how they can be reproduced using native Medplum/FHIR resources. Use it as a running inventory during the migration and to identify which builders need deeper implementation guides.

## Legend

| Status | Meaning |
|--------|---------|
| Identified | Builder recognized from HiiveHealth but not yet analyzed. |
| Analyzed | Builder mapped to Medplum primitives; high-level approach documented. |
| Documented | Full implementation guide exists in this repo. |
| In Progress | Active development or documentation underway. |
| Implemented | Working in the Provider app or backend. |

## Builder inventory

| # | HiiveHealth builder | What it configures | Medplum-native building block(s) | Status | Docs / Notes |
|---|---------------------|--------------------|----------------------------------|--------|--------------|
| 1 | Facility builder | Buildings → floors → rooms → stations/beds/chairs | Nested `Location` resources linked via `partOf` | Documented | See [hiivehealth-soap-note-in-medplum.md](hiivehealth-soap-note-in-medplum.md) facility section |
| 2 | Checklist builder | Visit-type-specific list of tasks the provider must complete | `PlanDefinition` + `ActivityDefinition` (`kind: "Task"`) → generates `Task` resources via `PlanDefinition/$apply` | Analyzed | Already partially implemented in `EncounterModal.tsx` / `createEncounter()` |
| 3 | Patient disposition config | Toggle disposition on/off per tenant + define disposition value list | `Basic` tenant config + tenant-scoped `ValueSet` + `Questionnaire.enableWhen` | Analyzed | Preferred Option 1 from disposition discussion |
| 4 | Visit type / encounter template builder | Define encounter types and their default checklists/orders | `PlanDefinition` per visit type; actions reference `ActivityDefinition`s | Analyzed | Extends checklist builder |
| 5 | Clinical decision flow builder | Decision-support questionnaires selected during an encounter | `Questionnaire` library; responses extracted via `$extract` or Bot | Documented | See [hiivehealth-soap-note-in-medplum.md](hiivehealth-soap-note-in-medplum.md) decision-flows section |
| 6 | SOAP section form builder | Add/edit fields within Subjective / Objective / Assessment / Plan cards | `Questionnaire` items per section | Analyzed | Tied to Option B architecture |
| 7 | Order set builder | Labs, imaging, referrals, follow-ups tied to visit type or assessment | `ActivityDefinition` (`kind: "ServiceRequest"`) referenced by `PlanDefinition` actions | Analyzed | Generated by `PlanDefinition/$apply` |

## Next steps / documentation gaps

1. **Checklist builder** — Create a focused guide with `PlanDefinition` + `ActivityDefinition` (`kind: "Task"`) examples and `TaskPanel` rendering notes.
2. **Patient disposition config** — Document Option 1 end-to-end: `Basic` config, tenant `ValueSet`, `Questionnaire.enableWhen`, and extraction to `Encounter.hospitalization.dischargeDisposition`.
3. **Visit type / encounter template builder** — Explain how visit types map to `PlanDefinition` resources and how selecting a visit type triggers `PlanDefinition/$apply`.
4. **Order set builder** — Detail `ActivityDefinition` (`kind: "ServiceRequest"`) patterns and how orders appear in the chart.
5. **SOAP section form builder** — Add a guide for authoring section-specific `Questionnaire`s, field types, and extraction mappings.
